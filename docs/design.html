1. Purpose and goals

kdiag diagnoses a broken Kubernetes namespace and fixes it one change at a time, with the user's approval. It collects a redacted snapshot, runs deterministic rule checks, optionally lets an LLM investigate with read-only kubectl tools under step, token, and spend caps, then proposes a single fix with a diagnosis, evidence, an exact diff, and the reasoning. Nothing changes until the user answers y. After each change kdiag waits for the rollout, re-checks the namespace, and feeds the new state into the next proposal. It installs from the GitHub repo with pip, needs only Python 3.9+, kubectl, and PyYAML, and works fully without an LLM.

2. Non-goals

  • Cluster-wide diagnosis. One namespace per session. Cluster-scoped problems (node pressure, CNI, DNS) are seen only through their symptoms.
  • Creating or deleting objects. The write path only runs kubectl patch on existing Deployments, StatefulSets, DaemonSets, Services, ConfigMaps, and PVCs. kdiag never modifies nodes, RBAC, or Secrets, and never creates missing ConfigMaps or Secrets (the container-config-error rule reports but does not fix).
  • Autonomous remediation. The LLM can only propose. --yes exists for CI and evals, not for clusters you care about.
  • Resource tuning. Automatic fixes are conservative heuristics; memory values such as 128Mi request and 512Mi limit are starting points.
  • Extra surfaces in v0.1. There is no web UI, daemon, or MCP server; kdiag is a CLI. The only runtime dependency is PyYAML, and LLM HTTP calls use the Python standard library.

4. Fix loop flow

When the LLM is on, it leads each round and sees the rule findings, the candidate fixes, and the session history. When it is off, finishes, or hits a cap, the first unhandled rule candidate is used. A fix already decided or attempted is never proposed again (fingerprint check). When the root-cause set has not changed since the LLM last had nothing to propose, the LLM is not called again for that state.

5. Safety model

Read and write separation

  • ReadOnlyKubectl is the only cluster access the LLM has. No method on it mutates the cluster.
  • KubeWriter accepts no free-form argv. It builds kubectl patch from a normalized kind, a name without / or spaces, a patch type (json, merge, strategic), and a patch object or list.
  • The LLM's propose_fix tool returns data only. There is no LLM tool that reaches KubeWriter.
  • Every proposal is validated with --dry-run=server before it is shown; the dry run output also produces the diff.

Allowlist

  • Verbs: get, describe, logs, events, explain, top, version, api-resources.
  • Resources: workloads, pods, services, endpoints, config maps, PVCs, nodes, events, ingresses, network policies, and similar. Secrets are not on the list.
  • Flags: a fixed set; output formats limited to json, yaml, wide, name, jsonpath, custom-columns (so no go-templates). --raw, --kubeconfig, --context, --token, exec are refused.
  • The namespace is pinned: kdiag appends -n itself and the Investigator refuses -n, --namespace, -A.

Redaction

  • Secret values are never read. Collection uses a template that prints only Secret names, types, and key names.
  • redact_obj and redact_text apply to bundles, LLM tool output, LLM error bodies, and the audit log.

Caps

  • Per investigation: --max-steps (default 12 LLM turns).
  • Per session: --max-tokens (200000) and --max-cost (USD 0.50). Cost uses OpenRouter's reported usage.cost when present, else token counts times preset prices.
  • Per session: --max-fixes (10). Tool output capped at 12000 characters.

No creation of nodes, Secrets, or new objects

  • Writable kinds: Deployment, StatefulSet, DaemonSet, Service, ConfigMap, PersistentVolumeClaim, and only via patch.
  • Evals refuse to run without an explicit --context or --kubeconfig, and only create or delete kdiag-eval-* namespaces.

6. LLM provider configuration

Any OpenAI-compatible chat completions API with tool calling works. Precedence: CLI flags, then KDIAG_LLM_* environment variables, then the provider preset. Each user brings their own key; kdiag reads it from an environment variable and never stores it.

ScriptedLLM is a third test double used only by unit tests: it replays pre-written assistant messages in order. The real client retries HTTP 429 and 5xx and network errors up to 3 times with backoff, and sends OpenRouter attribution headers only to OpenRouter.

8. Evals and scorecard

Each directory in scenarios/ has a manifest.yaml and an expected.yaml listing setup steps, expected root-cause rules, field checks the fixed objects must pass, and whether the namespace should be healthy afterwards. For each scenario the harness resets a kdiag-eval-<name> namespace, applies the manifests, waits to settle, runs the rules for detection, runs a FixSession with yes=True, checks the live objects, and deletes the namespace unless --keep is set.

The scorecard (scorecard.md and scorecard.json under --out) reports per scenario: detected versus expected rules, detection, correct fix, healthy after versus expected, fixes applied, steps (fix proposals plus LLM read-only tool calls), and time (diagnosis, fixes, and verification; setup excluded). A scenario passes when detection, fix, and health all match. Transcripts, report.json, and audit.jsonl are written per scenario. Unit tests use pytest with ScriptedLLM; GitHub Actions runs ruff and pytest on Python 3.9 and 3.12, with an optional kind end-to-end eval job.

9. Positioning versus k8sgpt

k8sgpt pioneered deterministic analyzers plus a one-shot LLM explanation of what they find. kdiag builds on the same idea and adds:

  • Agent loop: the model gathers its own evidence with allowlisted read-only tools, under step, token, and spend caps.
  • Gated fixes: one concrete patch at a time, with diff, evidence, and reasoning, applied only on approval.
  • Verification: rollout and re-check after every change, with failures fed back into the next round.
  • Offline bundles: collect once, analyze anywhere, with secrets redacted.
  • Evals: reproducible broken scenarios on kind with a scorecard, so rule and prompt changes are measured.
